# FOUNDRY

### **A Lightweight Manufacturing Execution System (MES) & BOM Manager.**

> **⚠️ STATUS: PRE-ALPHA / WORK IN PROGRESS**
> **THIS SYSTEM IS CURRENTLY IN ACTIVE DEVELOPMENT AND IS NOT YET READY FOR PRODUCTION USE.**
> Features may break, schemas may migrate, and logic is subject to change. This is a "build in public" project—**contributions, bug reports, and pull requests are highly appreciated.**

---

**FOUNDRY** is a local, browser-based ecosystem designed for managing Bills of Materials, visual production routing, inventory logic, and financial analytics for small-scale manufacturing and prototyping.

It operates on a **"Zero-Cloud" philosophy**—all data resides locally in portable SQLite databases. You own the infrastructure.

---

## CORE MODULES

### 1. FOUNDRY_VAULT (`index.html`)

**The central repository for project data, component specifications, and global MSRPs.**

* **BOM Management:** Create projects and define parts with bulk costs, quantities, and lead times.
* **Cost Analysis:** Real-time calculation of Design Valuation and Profit Margins based on component requirements.
* **Frontend-Dictated Schema:** The browser engine handles Vault database creation, structural migrations, and auto-repairs, pushing the final binary to the backend.

### 2. FOUNDRY_PRODUCTION (`production.html`)

**A node-based visual router for defining manufacturing logic.**

* **Visual Flow:** Drag-and-drop interface for connecting parts to manufacturing processes (CNC, 3D Printing, Assembly).
* **Smart Wiring:** Enforced **1-to-1 output logic** to ensure strict process linearity.
* **Inventory Awareness:** Real-time enforcement of BOM limits. You cannot place more parts on the router than exist in the Vault design.
* **Auto-Cleanup:** Smart port consolidation automatically removes gaps when nodes or wires are deleted.

### 3. FOUNDRY_COMMAND (`command.html`)

**The executive dashboard for operations, logistics, and strict financial intelligence.**

* **Strict Cash-Flow Ledger:** Financials are permanent and immutable. **Burn** only increases when you procure physical stock. **Revenue** only increases the exact moment a sale is committed to the ledger.
* **Inventory Runway:** Auto-calculates how many units can be built based on the "weakest link" component stock.
* **Smart Allocation:** Registering a sale checks available finished goods. If stock is insufficient, the system automatically calculates the shortage and prompts a Work Order generation.
* **Logistics Pipeline:** Dedicated queues for Allocation (Pending Sales), Production (Work Orders), and Fulfillment (Shipping).

---

## TECHNICAL ARCHITECTURE

* **Backend:** Python (Flask). Acts purely as a file server and binary blob persistence layer. It initializes the Sales ledger, but leaves Vault architecture entirely to the frontend.
* **Database:** SQLite (via `sql.js`). The database engine runs entirely in the browser (WASM). The backend simply saves the resulting binary files to disk.
* **Frontend:** Vanilla JS + Tailwind CSS. No build steps or bundlers required.
* **Persistence:** Data is split into two local files: `projects_vault.db` (BOM/Inventory/Financials) and `sales_command.db` (Order Ledgers).

## INSTALLATION & SETUP

FOUNDRY runs on a lightweight Python backend.

### Prerequisites

* Python 3.x
* Pip

### 1. Install Dependencies

```bash
pip install flask flask_cors


```

### 2. Launch the Engine

Run the application server. The backend will initialize the `sales_command.db` ledger. The `projects_vault.db` file will be dynamically generated by the frontend the first time you load the UI.

```bash
python app.py


```

### 3. Access the System

Open your browser and navigate to:
`http://localhost:8000`

## OPERATIONAL WORKFLOW

1. **Design (Vault):** Create a Project. Add Parts (Screws, PCBs, Motors). Define their individual costs, bulk purchase quantities, and set a Global MSRP for the finished product.
2. **Procure (Command):** Go to the Command tab. Click "+ STOCK" on raw components to simulate buying inventory. This permanently increases your financial "Burn".
3. **Route (Production):** Open Manufacturing Ops. Drag parts onto the canvas. Connect them through Process nodes (e.g., *Part -> Assembly -> Final*). Save the flow.
4. **Sell (Command):** Register a Sale in the Sales Entry tab.

* *If Finished Stock exists:* You can immediately click "Fill Order" to push it to shipping.
* *If Stock is Short:* Clicking "Fill Order" will alert you of the shortage and automatically prompt you to create a Batch Work Order for the missing units.

5. **Build (Command):** In the Production Pipeline, click "Finalize & Stock" on a Work Order. This consumes raw components and increments Finished Goods inventory, unlocking the ability to fill pending sales.
6. **Ship (Command - Logistics):** Authorize pending shipments to close out the tickets.
